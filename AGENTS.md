# Правила разработки «Кинополки»

## Стек

- React и TypeScript для интерфейса.
- Mantine UI для компонентов и раскладки, React Router для маршрутов, Motion для анимации.
- TanStack Query (React Query) для запросов, мутаций и кэша данных. Axios — HTTP-клиент. Zustand — для общего клиентского состояния.
- Дополнительные библиотеки согласовывай с пользователем до установки. Для стандартных интерфейсных иконок используй Tabler Icons. Кастомные иконки экспортируй из Figma и сохраняй в проекте. Не используй эмодзи в качестве иконок.

## Макеты и интерфейс

- Макеты и прототип в Figma — источник требований к внешнему виду и навигации. Сверяй композицию, типографику, цвета, отступы, состояния и ассеты с дизайном.
- Если нужной страницы нет в макетах, используй визуальный язык существующих экранов и уже разработанные компоненты.
- Если по макетам и прототипу нельзя определить поведение интерфейса или бизнес-логику, уточни сценарий у пользователя.
- При работе с Mantine применяй профильные навыки. Предпочитай компоненты Mantine нативной разметке. Для раскладки используй подходящие `Box`, `Flex`, `Stack`, `Group` и `Grid`.
- Небольшие правки выражай через style props Mantine. Сложные стили компонентов выноси в CSS Modules. Общие значения оформляй в теме Mantine.
- Используй только тёмную тему. Храни цвета, типографику, отступы и радиусы в Mantine Theme и используй её токены в компонентах и CSS Modules.
- Используй Motion для небольших анимаций интерфейса. Учитывай настройку уменьшенного движения.
- Кнопка «Смотреть» открывает модальное окно «Где смотреть» по фрейму Figma `7:1934`. Ссылки на источники открываются в новой вкладке.
- На мобильных экранах используй навигацию из фрейма Figma `111:2187`. Проверяй основные маршруты на узких экранах, планшетах и десктопах.
- При открытии «Где смотреть» со страницы серии сохраняй сезон и номер серии локально. На главной предлагай следующую серию и открывай для неё то же окно. В запросы к площадкам включай название сериала, год, сезон и номер серии.
- До появления бэкенда КиноГид показывает заранее подготовленный пример диалога.
- При регистрации ник состоит из строчных латинских букв `a–z` и знака `_`. Существующие ники остаются доступными для входа.

## Архитектура и данные

- Соблюдай Feature-Sliced Design (FSD). Глобальные провайдеры, тему и маршруты размещай в `app`, экраны и их локальную логику — в `pages`, общую инфраструктуру — в `shared`. Выделяй `features` и `entities` по мере реального переиспользования.
- Собирай страницы из компонентов с понятной ответственностью. Соблюдай направление импортов между слоями и используй публичные API слайсов.
- До появления бэкенда работай с типизированными моками через слой API. Держи моковые данные за границей API, чтобы при подключении бэкенда сохранить контракты компонентов и запросов.
- После изменений запускай Prettier через `pnpm format` и проверяй сборку через `pnpm build`.
